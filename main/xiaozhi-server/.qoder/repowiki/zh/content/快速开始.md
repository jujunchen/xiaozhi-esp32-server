## 简介
本指南旨在帮助新用户快速在本地环境或Docker中部署并运行xiaozhi-server。通过本指南，您将学习如何满足先决条件、选择合适的安装方式、配置关键参数、获取必要模型文件，并完成一次完整的语音交互测试。本指南特别注重对初学者的友好性，每一步都配有清晰的命令示例和预期输出描述。

## 先决条件
在开始部署之前，请确保您的系统满足以下先决条件：

- **Python版本**：必须安装Python 3.10。本项目不兼容其他Python版本。
- **系统依赖**：
  - **FFmpeg**：用于音频编解码处理。请确保`ffmpeg`命令在系统路径中可用。
  - **Conda**（推荐）：用于管理Python环境和依赖，特别是处理`libiconv.so.2`等底层依赖。
- **网络连接**：用于下载Python包、Docker镜像以及可选的云服务API调用。
- **存储空间**：确保有足够的磁盘空间来存放模型文件（如SenseVoiceSmall模型，大小约1GB）。

## 安装方式一：Python虚拟环境源码安装
此方式适用于希望在本地环境中进行开发和调试的用户。

### 1. 创建Python虚拟环境
```bash
# 创建名为xiaozhi的虚拟环境
conda create -n xiaozhi python=3.10
# 激活虚拟环境
conda activate xiaozhi
```

### 2. 安装FFmpeg
```bash
# 在conda环境中安装ffmpeg
conda install -c conda-forge ffmpeg
```

### 3. 安装Python依赖
```bash
# 安装项目依赖
pip install -r requirements.txt
```
**预期输出**：所有依赖包成功安装，无报错信息。

### 4. 验证安装
```bash
# 检查ffmpeg是否安装成功
ffmpeg -version
# 检查Python环境
python --version
```
**预期输出**：显示FFmpeg版本信息和Python 3.10.x版本。

## 安装方式二：Docker容器化部署
此方式适用于希望快速部署且不希望污染本地环境的用户。

### 1. 编写docker-compose.yml
使用项目根目录下的`docker-compose.yml`文件：
```yaml
version: '3'
services:
  xiaozhi-esp32-server:
    image: ghcr.nju.edu.cn/xinnan-tech/xiaozhi-esp32-server:server_latest
    container_name: xiaozhi-esp32-server
    restart: always
    security_opt:
      - seccomp:unconfined
    environment:
      - TZ=Asia/Shanghai
    ports:
      # WebSocket服务端口
      - "8000:8000"
      # HTTP服务端口，用于OTA和视觉接口
      - "8003:8003"
    volumes:
      # 配置文件目录
      - ./data:/opt/xiaozhi-esp32-server/data
      # 模型文件挂载
      - ./models/SenseVoiceSmall/model.pt:/opt/xiaozhi-esp32-server/models/SenseVoiceSmall/model.pt
```

### 2. 启动Docker容器
```bash
# 在docker-compose.yml所在目录执行
docker-compose up -d
```
**预期输出**：容器成功启动，可通过`docker ps`查看运行中的容器。

### 3. 查看容器日志
```bash
docker logs xiaozhi-esp32-server
```
**预期输出**：日志中应包含WebSocket和HTTP服务启动成功的提示。

## 模型文件获取与放置
本项目依赖本地模型文件进行语音识别（ASR）和语音活动检测（VAD）。

### 1. SenseVoiceSmall模型
- **作用**：用于本地语音识别（ASR），提供离线、低延迟的中文语音转文字能力。
- **获取方式**：需从官方渠道或指定链接下载`model.pt`文件。
- **放置位置**：将`model.pt`文件放置于`models/SenseVoiceSmall/`目录下。
- **配置关联**：在`config.yaml`中，`ASR.FunASR.model_dir`指向此目录。

### 2. Sherpa-ONNX模型
- **作用**：提供另一种本地ASR选项，支持多语言识别。
- **获取方式**：参考`models/sherpa-onnx/README.md`中的说明，可能需要使用`conda`安装`pynini`。
- **放置位置**：根据`config.yaml`中`ASR.SherpaASR.model_dir`的配置放置相应模型文件。

### 3. Silero-VAD模型
- **作用**：用于语音活动检测，判断音频流中是否有语音。
- **放置位置**：`models/snakers4_silero-vad/`目录下的模型文件已包含在项目中，无需额外下载。

## 配置文件详解
`config.yaml`是项目的核心配置文件，支持通过`data/.config.yaml`进行覆盖。

### 最小化配置示例
```yaml
server:
  ip: 0.0.0.0
  port: 8000
  http_port: 8003

selected_module:
  ASR: FunASR
  LLM: ChatGLMLLM
  TTS: EdgeTTS
  VAD: SileroVAD

ASR:
  FunASR:
    type: fun_local
    model_dir: models/SenseVoiceSmall

LLM:
  ChatGLMLLM:
    type: openai
    model_name: glm-4-flash
    url: https://open.bigmodel.cn/api/paas/v4/
    api_key: your_api_key_here

TTS:
  EdgeTTS:
    type: edge
    voice: zh-CN-XiaoxiaoNeural
```

### 关键参数说明
- **ASR提供商**：`selected_module.ASR`选择语音识别模块，如`FunASR`（本地）或`DoubaoASR`（云端）。
- **LLM提供商**：`selected_module.LLM`选择大语言模型，如`ChatGLMLLM`（免费）或`DoubaoLLM`（稳定）。
- **TTS提供商**：`selected_module.TTS`选择文本转语音模块，如`EdgeTTS`（微软）或`DoubaoTTS`（火山引擎）。
- **API密钥**：在对应模块下配置`api_key`，如`LLM.ChatGLMLLM.api_key`。

## 常见初始化错误及解决方案
### 1. 模型文件缺失
- **错误现象**：启动时报错`FileNotFoundError`，找不到`model.pt`。
- **解决方案**：确保`models/SenseVoiceSmall/model.pt`文件存在。

### 2. 端口占用
- **错误现象**：启动时报错`OSError: [Errno 98] Address already in use`。
- **解决方案**：修改`config.yaml`中的`server.port`或`server.http_port`为未被占用的端口。

### 3. 依赖版本冲突
- **错误现象**：`pip install`时报错版本不兼容。
- **解决方案**：严格按照`requirements.txt`中的版本安装，使用虚拟环境隔离。

### 4. FFmpeg未安装
- **错误现象**：启动时提示`ffmpeg无法正常运行`。
- **解决方案**：使用`conda install -c conda-forge ffmpeg`安装。

### 5. Docker权限问题
- **错误现象**：容器启动失败，提示权限错误。
- **解决方案**：确保Docker服务已启动，并检查`security_opt`配置。
